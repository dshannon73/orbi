Build Your Own Orbi

An AI SE Command Center you can build yourself in a weekend with Claude Code

What You'll Build

Orbi is an AI-powered command center for Salesforce Solutions Engineers. It automates quarterly "App Rigor" admin — the tedious but mandatory work of logging activities, filing Deal Contributions, and drafting DSR status updates — by connecting Google Calendar, Salesforce org62, Slack, and Gmail into a single intelligent workflow.

Activity Logging

Pull Google Calendar events, AI-classify them by SE Task Type, match to accounts/opportunities, and batch-log to Salesforce with one click.

DC Gap Detection

Identify opportunities where you have activity but no Deal Contribution. Auto-suggest split percentages based on engagement.

DSR Status Drafts

Research Slack, Calendar, and Drive for each active DSR, then draft Status Comments and Next Steps with cited sources.

Slack Canvas Rollups

Generate formatted activity and DC rollup canvases posted directly to Slack for manager visibility.

Embedded Terminal

A full Claude Code session inside the UI — run SE skills, query SF, and automate workflows without leaving the app.

Prerequisites

Salesforce org62

Active org62 access with SE_Task_Type__c, Deal_Contribution__c, and Deal_Support_Request__c objects. SF CLI installed and authenticated.

Google Cloud Project

OAuth 2.0 credentials with Calendar (read) scope. Redirect URI pointed at your dev server.

Slack MCP (aisuite)

Slack workspace access via the aisuite MCP adaptor. Bot token with channels:read, chat:write, and canvas scopes.

Claude Code CLI

Anthropic's Claude Code CLI installed at ~/.local/bin/claude. Used for the embedded terminal and DSR research agent.

Node.js 18+

Runtime for both the Express backend (TypeScript via ts-node) and the React/Vite frontend.

Step-by-Step Setup

Two versions available:
  • v1 — Google OAuth calendar · ports 3001/5173 · orbi-deck-66e67b8b9735.herokuapp.com
  • v2 — Google Calendar MCP (no GCP project needed) · ports 3002/5174 · orbi-v2-33a2c3f213ef.herokuapp.com
1

Get the Source

Download the source from Heroku using the CLI, or copy via git:

# Option A — Heroku CLI (recommended)
heroku git:clone -a orbi-v2 orbi && cd orbi
git checkout v2-mcp-calendar

# Option B — if you have git access to the repo
git clone <repo-url> orbi && cd orbi
# Install all dependencies
npm install
cd server && npm install && cd ..
cd client && npm install && cd ..
2

Salesforce CLI Auth

Authenticate against your org62 instance:

sf org login web --alias org62 --instance-url https://org62.my.salesforce.com

The server reads the SF CLI session file directly via sf org display --target-org org62 --json — no manual token management. It auto-refreshes on each request.

3

Calendar Setup — pick v1 or v2

v1 — Google OAuth

Requires a GCP project with Calendar API enabled.

# server/.env
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REDIRECT_URI=http://localhost:3001/api/calendar/oauth/callback
v2 — MCP (recommended)

No GCP project needed. Requires aisuite + google-workspace MCP authenticated.

# No Google env vars needed.
# Ensure Claude CLI is installed:
which claude  # should resolve
# Ensure google-workspace MCP works:
claude -p "list my calendar events today"
4

Slack Integration

Create a Slack app with channels:read, chat:write, and canvas permissions:

# server/.env
SLACK_BOT_TOKEN=xoxb-your-bot-token
SLACK_SIGNING_SECRET=your-signing-secret

For Slack MCP search in the embedded terminal, configure the aisuite MCP adaptor separately.

5

Full server/.env template (v2 — MCP calendar):

# Salesforce (SF CLI auth is primary; these are fallback)

Run Dev Server

npm run dev

# v1 (main branch)
npm run dev:server  # Express on :3001
npm run dev:client  # Vite on :5173  →  http://localhost:5173

# v2 (v2-mcp-calendar branch)

Log in with your SF CLI token for the org62 alias. Calendar and briefing work immediately — no OAuth flow needed in v2.

Key Gotchas

Four hard lessons learned during the build:

MCP is not directly callable from Node

You cannot import MCP tools into a Node server. The solution: spawn Claude CLI as a subprocess with --print --dangerously-skip-permissions --output-format stream-json. Pipe your prompt to stdin, stream JSON events from stdout. The terminal and DSR review features both use this pattern.

Auth across 5 systems

SF CLI session file, Google token refresh, Slack bot token, LLM gateway key, and Express session cookies all need to stay valid simultaneously. SF CLI handles its own refresh transparently. Google tokens are refreshed proactively on each /status check. Session uses file-store with 1-year TTL.

Claude safety filters

Spawning Claude CLI fails if you pass prompts that look like jailbreak attempts. Use natural language prompts, set a neutral working directory (not /tmp), and avoid system-level instructions that trigger refusal. The DSR prompt works because it reads like a legitimate workflow instruction.

State management: pick ONE layer

Early versions had state in React state, Zustand stores, URL params, AND session simultaneously. The fix: Zustand for UI state (filters, panel open/close), Express session for auth identity, and Salesforce as the single source of truth for data. No local caching of SF records.

Extend It

Add a New Agent

Agents in Orbi are Express routes that spawn Claude CLI with a tailored prompt. To add one:

  1. Create server/src/routes/yourAgent.ts with a POST endpoint
  2. Set SSE headers (Content-Type: text/event-stream)
  3. Pre-fetch any Salesforce data the agent needs (skip expensive LLM-driven lookups)
  4. Build a detailed prompt with the pre-fetched context
  5. Spawn claude --print --dangerously-skip-permissions --output-format stream-json --verbose
  6. Pipe the prompt to stdin, stream stdout events as SSE data: frames
  7. Register the route in server/src/index.ts

Add a New Data Source

  1. Add the API client to server/package.json dependencies
  2. Create a service file in server/src/services/ for auth and client setup
  3. Create a route in server/src/routes/ that exposes the data via REST
  4. For OAuth-based sources, follow the Google Calendar pattern: /connect endpoint redirects to consent, /callback stores tokens in session, /status checks validity
  5. Add the corresponding page in client/src/pages/ with React Query for data fetching
