01 — The Problem

Data everywhere.
Insight nowhere.

As an SE, your data lives in six different tabs. You context-switch constantly just to answer basic questions about your own pipeline.

  • 🏢
    Salesforce org62 Activities, opportunities, accounts — all locked inside SF. No quick glance.
  • 💬
    Slack overload Deal updates, customer pings, team threads — impossible to triage from within SF.
  • 📅
    Calendar blindness No native view linking calendar events to accounts or opportunities.
  • ✈️
    Travel approvals Scattered approval requests with no unified status view.

One hub. All signal.

Orbi pulls everything into a single dark-mode interface. Your pipeline, activities, deal contributions, travel requests, calendar, and an AI assistant — all in one place, all authenticated through a single session.

Built specifically for the way SEs actually work: account-centric, deal-focused, always context-switching.

05 — Build Journey

How it evolved.

Started with a simple name and a data problem. Ended with a full SE platform.

Chapter 01

Born as org62-app

Started with a single question: why is it so hard to see my own Salesforce data? Built a bare Express + React shell to proxy org62 API calls.

express react org62 api
Chapter 02

Auth + persistent sessions

Added express-session with FileStore for year-long sessions. No DB, no OAuth complexity — just a session file and a Salesforce token.

express-session session-file-store sf auth
Chapter 03

All 12 routes built out

Systematically built every route — activities, opportunities, deal contributions, accounts, users, travel approvals, calendar, slack, meta, dashboard. Each one a clean TypeScript module.

06 — What I Learned

The real lessons.

Building a tool you actually use every day sharpens your instincts fast.

01

The proxy pattern scales surprisingly well

Keeping Express as a thin proxy — no ORM, no database, no abstraction layer — meant every route was fast to build and easy to debug. Simplicity is a feature.

02

Session files beat databases for personal tools

express-session with FileStore meant zero infrastructure. One year TTL, one JSON file per session. For a single-user app, it's the right call every time.

03

AI assistants need grounded data to be useful

A generic LLM can't help with your pipeline. Wiring Claude to live SF data via tool use transforms it from a chatbot into an actual work assistant.

04

Name things properly — it changes how you build

Calling it "org62-app" kept it feeling like a script. The moment it became "Orbi" the bar for quality went up. Names set intent.
